# Change the dashboard

Written 2026-10-08 from the real task it describes: the Read-surface hierarchy of 2026-10-05/06
(`1d17a69` Explore charts-only, `26ff92e` Read pane hierarchy, `f636e6d` one information
hierarchy; DASHBOARD_SPEC §22). The rules a surface must follow live in **DASHBOARD_SPEC §22**;
this skill is the order to apply them in.

**Done when:** the user approved the ASCII layout; `npx tsc --noEmit` and `npm test` in `web/`
pass; every page the change touches was checked in the preview at 1440 and 375, light and dark,
with a clean console and no page-level horizontal scroll; and the SIBC gate
(`python3 analysis/core/gate.py --pipeline sibc`, which includes the build) is green.

Stop at every ⏸ for the user. Claude may start this skill on its own (DECISIONS, "Working
model"); committing and pushing still wait for the user.

## 0. Place the change

- **Which surface, which pipelines?** Read is the authoritative surface for insights; Explore is
  charts only (DECISIONS). A change to a shared primitive (`components/read/parts.tsx`,
  `ReadModeShell.tsx`, `SectionCard.tsx`) lands on all three dashboards: SIBC `/`, payments
  `/payments`, NBFC `/nbfc`. List them now; each one is verified in step 4.
- **Presentation, or a number?** If any sentence, cell or reading changes, the change starts in
  Python: sentences are rendered there and shipped as strings (DECISIONS; `web/AGENTS.md`
  "The browser never formats a number"). Find the renderer first (`analysis/signals/stamp_table.py`
  for table cells, `analysis/core/table_columns.py` for column names and hover hints) and the
  guard that checks it (`analysis/guards/validate_cut_table.py`, `analysis/guards/validate_state_band.py`).
  A guard change follows DECISIONS: measured catch and false-rejection rates first.
- **One mechanism, not one page.** A fix goes in the shared primitive or the generic renderer,
  then each adapter (`{Sibc,Atm,Nbfc}ReadMode.tsx`) only declares. A fix made in one adapter is the
  per-pipeline one-off the Engineering Principle forbids, unless the pipelines genuinely differ
  (SIBC nests, payments filters: an accepted inconsistency).

## 1. Look before drawing

Open the page as it is now, at both widths, before proposing anything:

```
preview_start {name: "india-credit-lens"}     # or {url: "http://localhost:3000"} if port 3000 is held

```

Take the screenshots you will compare against, and note the live numbers on the part being
changed. Read the DASHBOARD_SPEC section that owns that surface (§16 state band, §17/§20 tables,
§21 real economy, §22 hierarchy) so the proposal names the rule it follows or changes.

## 2. ASCII layout, with the live numbers (⏸ approval)

Per CLAUDE.md, no code until the layout is approved. The proposal holds:

- **The ASCII**, at 1440 and at 375 if they differ, drawn with the real readings, never `x.x%`.
  Placeholders hide exactly what needs designing: a 2px bar, a 0.97 pp move on a 0–80% axis,
  a "—" that needs its reason.
- **The §22.6 checklist, answered:** the `TEXT` level of each piece of text (a piece that fits
  none is a new level, proposed in `web/lib/tokens.ts` in the open); one L1 on screen;
  claim → evidence → reference; the §22.3 chart frame; every caption triaged by §22.4; quiet,
  absent and empty each rendered differently (§22.5).
- **What it replaces or removes**, and on which pages.

A user ruling made while approving ("the tile cap stays at 3") goes into DECISIONS or the
spec section, in this session.

## 3. Build

- Text sizes come from `TEXT.*`, the type and radius scale from `web/lib/tokens.ts`, colours from
  CSS custom properties. `lib/tokens.test.ts` fails a raw `FS.title / FS.section / FS.card` in
  `components/read/`, and DECISIONS forbids literals outside the scale.
- A new table column is declared once, with its hover `hint`, in `analysis/core/table_columns.py`,
  then `python3 analysis/core/table_columns.py --write` regenerates `web/lib/table_columns.ts`.
  Never edit the generated file.
- A sidecar change (`web/public/data/{pipeline}_table.json`, `_state.json`, `_planes.json`) is
  regenerated by the gate stages that write it (5.9, 5.9a, 5.9c), never edited by hand.
- Read the relevant guide in `web/node_modules/next/dist/docs/` before using a Next.js API from
  memory (`web/AGENTS.md`: this is Next.js 16).

## 4. Verify, page by page

In `web/`: `npx tsc --noEmit` and `npm test`. Then, for **every page listed in step 0**:

| Check | How |
|---|---|
| 1440 and 375 | `resize_window` 1440×900, then preset `mobile`; reload after switching |
| light and dark | dark mode is the app's own toggle, NOT the OS scheme: set `localStorage["icl-dark"]="true"` and reload, or click the header toggle; `resize_window colorScheme` does nothing here |
| console clean | `read_console_messages {onlyErrors: true}` after a fresh reload |
| no horizontal scroll | `javascript_tool`: `document.documentElement.scrollWidth <= window.innerWidth` |
| the interaction works | click through what changed: open a tile, a row, a chart, Esc pops one level |
| numbers unchanged | the readings on screen equal the step-1 screenshots, unless the change was to them |

Compare against the step-1 screenshots and the approved ASCII, then show the user the after
screenshots. Finally the SIBC gate (it runs vitest, tsc and the build as stages 5b and 6):

```bash
python3 analysis/core/gate.py --pipeline sibc
```

## Traps (each one happened)

- **A hidden browser pane pauses animation.** Recharts bars animate in; a screenshot taken while
  the pane is hidden, or right after a resize (which restarts the animation), shows empty bars.
  On 2026-10-08 this read as "bar charts broken at 375" and they were not. Reload, wait, retake
  before calling it a bug.
- **The console keeps errors across HMR.** A `ReferenceError` whose stack runs through
  `performReactRefresh` is a mid-edit reload, not the current code. Reload and re-check.
- **Two dev servers cannot share `web/`.** If another session holds port 3000, `preview_start`
  by name fails; open `http://localhost:3000` by url instead (HMR serves this session's edits).
- **A green gate does not mean the chart draws what the card says.** Stage 5.7 checks the
  declared cut, not the rendered series: payments bank-category cards were drawn over the top-5
  banks and showed one 100% bar with 5.7 green (found 2026-10-05 only by looking). Look at every
  chart the change touches.
- **Cards and annotations that render nowhere still exist.** Explore is charts only; subject-plane
  cards and the 27 `rbi_sibc.ts` annotations are generated but not shown. Do not "fix" a surface
  by bringing them back; that is an open decision in PLAN.
- **Folding never deletes** (§22.4). A line moved under "Notes on this table" is still rendered
  in Python and still gate-checked; removing it is done at its source.
- **Two surfaces quoting one fact may resolve it two ways.** The POS "—" (2026-10-08) was not a
  POS bug: the band read a table's total rate from the registry, the table from three
  hand-declared anchors, and they disagreed on 23 of 26 tables. When a cell disagrees with the
  band, find both resolvers, make one, and assert agreement over every pipeline (`test_cut_table`).
- **Widening a fix's reach exposes what was behind it.** Filling 23 total rows made their history
  chart reachable, and it had always titled the total by the cut's id and shown raw floats in the
  tooltip, for the 3 anchors too. A defect found in step 4 is a new visible change: back to step 2
  with an ASCII, then build.
- **Touch has no hover.** Heading hints show on hover or keyboard focus only; on a phone, tapping
  a heading sorts. Anything a reader must see on mobile cannot live only in a hint.
